# 展示会営業OS — 設計仕様（Rev.2）

株式会社イケテルコーポレーション 展示会事業向け 営業半自動化システム。

- 対象業務: アポ獲得 → 商談前準備 → 商談 → 提案資料作成 → 受注 → 案件管理
- 利用者: 池田社長 1名
- 目標: 1案件あたり 15時間 → 5.5時間（▲63%）
- ステータス: **Rev.2 — すり合わせ4点を反映済み。残論点3件（末尾参照）は Phase 1 着手をブロックしない**

すり合わせ資料（ビジネス向け）: https://claude.ai/code/artifact/57c25da1-fc4b-4e13-8bad-b54ec41bc1d3

## 0. すり合わせ結果（Rev.2 で反映）

| 論点 | 決定 | 設計への反映 |
|---|---|---|
| パースの作り手 | 案件によって自作／外注の両方 | ⑤の出力を2系統に。自作案件は平面図＋AIイメージ、外注案件は**外注指示書を自動生成**（逆算要件入りのため外注の手戻りも減る） |
| 必要なパース品質 | 案件規模による | 案件登録時に規模区分を保持し、⑤の出力モードを自動切替（§4.5） |
| 商談中の入力 | **録音して自動で項目化** | 文字起こし→項目マッピングを Phase 2 後半オプションから**中核機能に格上げ**。③は入力フォームではなく「手元カンペ＋聞き漏らし検知」に役割変更 |
| 提供データ | 提案書PPTXテンプレート＋受注できた提案書サンプル3件 | ④の型は社長の勝ちパターンから起こす。**施工写真・実績数値は初期提供なし**のため、⑤出力4（事例レコメンド）と逆算係数の自社化は⑥で蓄積しながら育てる方式へ変更 |

施工写真と実績数値が初期に無いことの対処: ⑥の案件完了タスクに「施工写真の登録」「実績数値の登録」を組み込み、**未登録では案件を閉じられない導線**にする。10件程度で事例レコメンド・自社係数とも実用水準に入る想定。

## 2. 設計原則

1. **AIはたたき台まで。** 意思決定と最終品質は社長。AIに判断させると精度が落ち、作り直しで時短が消える。
2. **出典のない情報は出さない。** リサーチ結果には根拠URLを必ず付与。取得できなければ空欄で表示し、推測で埋めない。
3. **取れなかった情報は質問に昇格。** 自動取得の失敗を、そのままヒアリング項目に変換する。100%自動化を狙わない。
4. **同じ情報は二度入力しない。** ①〜⑥が1本の案件レコードを共有する。転記が発生した時点で設計ミス。

## 3. コア: 成果逆算エンジン

競合が出展社任せにしている「出展目標 → ブース仕様」の導出を計算式にする。本システムの中核であり、提案書の差別化ポイント。

### 逆算チェーン

```
目標受注金額
  ÷ 平均受注単価      → 必要受注件数
  ÷ 受注率            → 必要商談数
  ÷ 商談化率          → 必要有効リード数
  ÷ 有効リード率      → 必要名刺数
  ÷ 立寄→名刺化率     → 必要立寄り数
  ÷ 通行→立寄り率     → 必要通行接触数
```

### 初期ベンチマーク（要: 社長の実績値で上書き）

| 係数 | 初期値 | 出所 |
|---|---:|---|
| 受注率 | 25% | 業界一般値（仮） |
| 商談化率 | 30% | 業界一般値（仮） |
| 有効リード率 | 25% | 業界一般値（仮） |
| 立寄→名刺化率 | 35% | 業界一般値（仮） |
| 通行→立寄り率 | 3–5% | 業界一般値（仮） |

実績数値は初期提供がないため、係数は3段構えで運用する:

1. 業界平均で起動
2. 画面上で社長がその場で上書き（商談中の肌感覚を即反映）
3. ⑥で貯まった自社実績に自動で置換

数値の出所（「業界平均」／「イケテル実績 n=12」）を画面と提案書に必ず明記する。

### 逆算から導出する仕様

| 導出項目 | 根拠となる中間値 |
|---|---|
| 小間数・間口・開放面 | 必要通行接触数 |
| アイキャッチ設計（視認距離・訴求強度） | 必要立寄り数 |
| 商談席数・滞在時間設計 | 必要商談数 ÷ 会期日数 ÷ 1商談所要時間 |
| スタッフ人数・配置 | 1人1日あたり接触可能数 |
| 名刺獲得動線（デモ導線・資料DL・抽選） | 必要名刺数 |
| 予算妥当性・ROI | 目標受注金額 vs 出展総額 |

## 4. 機能仕様

### ① URL投入 → 顧客DB登録（90分 → 10分）

- 入力: 企業URL（必須）／展示会名・会期・小間数（任意）／アポ経緯メモ
- 自動取得: 会社概要・資本金・従業員数・拠点／事業・商材／想定顧客・取引実績／プレスリリース／採用情報
- 出力: 顧客カード
- 未取得項目は空欄で保持し、③のヒアリング項目へ自動昇格

### ② 自動リサーチ → 仮説課題抽出（60分 → 10分）

- 自動取得: 過去出展履歴（展示会名／年／規模／テーマ）／競合の出展状況／直近の事業トピック
- 出力: 仮説課題 3〜5本（根拠URL必須）／未取得情報リスト／競合比較メモ
- 社長操作: 仮説の採否チェック、手動追加
- **既知リスク**: 過去出展情報はWeb上に断片的。取得率の見込みは 50〜70%。未取得分はヒアリングで回収する設計とする

### ③ ヒアリング項目の自動生成（30分 → 5分）

出力形式: 商談中に見る手元カンペ（モバイル可）／印刷用PDF／**録音の文字起こしを照合するチェックリスト**

設問構成:

| 区分 | 内容 |
|---|---|
| A | 出展目的とゴール |
| B | 逆算に必要な数値（平均単価・受注率・過去実績名刺数） |
| C | ターゲットと課題 |
| D | 出展条件（会期・小間数・位置・予算・搬入制約・レギュレーション） |
| E | ブランド要件（トンマナ・NG・既存VI・什器再利用） |
| F | ②の仮説の検証 |
| G | ①②で取得できなかった情報 |

③は質問リストではなく **④が必要とする項目の定義**。商談は録音するため社長がシートを埋める必要はなく、商談後に文字起こしと自動照合して **未回答項目のみを提示**する（例: 「D-4 搬入制約」「B-2 平均受注単価」が未取得）。聞き漏らしによる出戻りをゼロにすることが最大の時短。

### ④ ヒアリング入力 → 提案骨子PPTX（420分 → 90分）

- 入力（**録音が主**）: 商談録音をアップロード → 文字起こし → ③の各項目へ自動マッピング → 未回答項目を一覧提示 → 社長が補完。手入力も併用可
- 処理: 逆算エンジン実行 → KPI・必要仕様を算出 → イケテル4STEP構成へ流し込み
- 出力: `.pptx`（イケテル既存テンプレート準拠）

想定スライド構成:

1. 表紙
2. 御社の出展目標
3. 現状の課題（②の仮説＋ヒアリング結果）
4. **逆算KPI（計算式が見えるページ）**
5. 出展コンセプト
6. ターゲット・ペルソナ
7. ブース設計要件（逆算からの導出）
8. 平面・動線プラン（⑤出力1）
9. パースイメージ（⑤出力3／将来は出力4の実事例）
10. 当日運営（スタッフ配置・スクリプト）
11. 展示会後フォロー
12. スケジュール
13. 概算費用
14. 実績

### ⑤ プラン作図 — 4つの出力を案件規模で出し分け（300分 → 180分）

**「トンマナとコマ数を入れたら提案書掲載品質のパースが出る」は現時点の技術では成立しない。** 寸法（1小間 = W2,970 × D2,970）・什器整合・ブランド世界観を同時に満たす画像生成は手直し前提。自作／外注の両方があり必要品質も規模で変わるため、単一の正解を作らず4出力を用意して規模で切り替える。

#### 案件規模による出し分け（閾値は仮置き・要確認）

| 規模 | 提案時に出すもの | 精緻CG | 作図工数 |
|---|---|---|---:|
| 小規模（〜2小間） | 平面図・動線図 ＋ AIイメージパース | 不要 | 5h → 1h |
| 中規模（3〜6小間） | 平面図・動線図 ＋ AIイメージパース（必要に応じ外注指示書） | 案件次第 | 5h → 2.5h |
| 大規模（6小間〜・シンボル出展） | 平面図・動線図 ＋ **外注指示書** → 外注でCG | 必須 | 5h → 3.5h |

#### 4つの出力

| # | 内容 | 確実性 |
|---|---|---|
| 1 | **平面図・動線図の自動生成**（ルールベース／SVG）。小間数・小間タイプ（列/角/島/半島）・間口・什器構成を入力 → 平面プラン・ゾーニング・動線を作図。逆算エンジンの「必要商談席数」との整合を自動チェックし不足時に警告 | 高（掲載可） |
| 2 | **外注指示書の自動生成**。逆算エンジンが出した設計要件（必要商談席数・動線要件・アイキャッチ視認距離・トンマナ・NG事項・什器構成・寸法制約・レギュレーション）を指示書に構成。外注案件の主力。要件が数値で入るため上がりのズレと手戻りが減る | 高 |
| 3 | **AIイメージパース**。コンセプト・トンマナ・出力1の平面図を条件に画像生成。提案書には「イメージ」と明記して掲載。小〜中規模はこれで提案が通る想定 | 中（手直し前提） |
| 4 | **過去事例レコメンド**。施工写真に業種・小間数・トンマナ・構造・予算帯をタグ付けし条件一致の3案を提示。実物写真のため納得感は最高。**ただし写真データの初期提供がないため Phase 4 以降**（⑥で蓄積し10件程度で有効化） | 高（データ待ち） |

### ⑥ 受注後の案件管理

会期日から逆算してタスクを自動展開:

- 出展社説明会
- 電気／給排水／施工の各申請締切
- デザイン確定 → 実施設計・施工図
- 印刷入稿／什器発注
- 搬入 → 会期 → 撤去
- 請求／振り返り

各タスクに「会期 D−n日」のデフォルト、外注先アサイン、締切アラートを保持。

**案件完了タスクに蓄積ステップを組み込む（必須項目とし、未登録では案件を閉じられない導線にする）:**

- 実績数値（名刺数・有効リード数・商談数・受注件数・受注金額） → 逆算エンジンの係数へ還流
- 施工写真（業種・小間数・トンマナを自動タグ付け） → ⑤出力4の事例ライブラリへ蓄積

「あとでまとめて登録」は続かないため、案件クローズの導線に組み込むことが要件。

## 6. 技術構成

| レイヤー | 選定 | 理由 |
|---|---|---|
| 画面 | Streamlit | 単独利用の社内ツールに最適。既存リポジトリと同構成で着手が速い |
| データ | SQLite（将来 Supabase） | 1人利用で十分。移行可能な形で実装 |
| AI | Claude API ＋ Web検索 | リサーチ・仮説抽出・文章生成 |
| 提案書 | python-pptx | イケテル既存テンプレート（.potx）へ流し込み |
| 作図 | SVG自動生成 | 寸法が正確に出る |
| パース | 画像生成API | ⑤出力3（AIイメージパース） |
| 音声 | 文字起こしAPI | 商談録音 → ヒアリング項目マッピング。**主入力のため Phase 2 の中核** |
| 設置 | パスワード保護したクラウド1インスタンス | 顧客情報を扱うため公開状態には置かない |

概算ランニングコスト: 月 5,000〜18,000円程度（案件数による）。

## 7. 開発フェーズ

| Phase | 期間 | 内容 | 到達点 |
|---|---|---|---|
| 1 | 2–3週 | ①②③ 商談前準備の自動化 | 商談前 3h → 0.5h |
